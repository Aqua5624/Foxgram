# Foxgram

Foxgram is a planned Nekogram-style iOS client, built as a fork-configuration
layer on top of the official open-source **Telegram-iOS** client. This
repository is intentionally small: it contains **no Telegram source code**.
It holds only the CI workflow and the configuration tooling needed to build
Telegram-iOS as "Foxgram".

## Build test (Phase 0.5)

The `Build Foxgram` workflow (manually dispatched) does the following on a
GitHub-hosted `macos-26` runner:

1. Clones `TelegramMessenger/Telegram-iOS` at the pinned app-12.10 commit
   `72e573e8b69f8f12736ac6086c826ab10e37d242` (versions.json: Xcode 26.6,
   Bazel 8.4.2, macOS 26 — matching the `macos-26` runner image).
2. Selects `/Applications/Xcode_26.6.app` as the active Xcode.
3. Generates the build configuration (`scripts/generate_config.py`):
   bundle id `org.aqua5624.foxgram`, app configuration in the shape of
   upstream's `template_minimal_development_configuration.json`.
4. Re-issues upstream's fake-codesigning provisioning profiles for the
   Foxgram bundle id (`scripts/remap_profiles.py`). Upstream profiles are
   bound to `ph.telegra.Telegraph`; `Make.py` only accepts profiles whose
   application-identifier matches the configured bundle id, so the profiles
   are decoded, rewritten, and re-signed with upstream's own SelfSigned
   certificate — the same technique as upstream's
   `build-system/Make/GenerateProfiles.py`. No upstream source code is
   modified.
5. Builds the upstream tree with upstream's own tooling
   (`ImportCertificates.py` + `Make.py build --configuration=release_arm64`)
   and publishes the resulting unsigned IPA as a GitHub Release asset
   and as a workflow artifact.

Phase 0.5 (unmodified build, tag `build-test-1`) succeeded and the IPA was
verified to log in on-device.

## Phase 1: patches + branding

Since the workflow clones upstream fresh on every run, all Foxgram
changes live in this repository and are applied to the cloned tree by the
"Apply Foxgram patches and branding" step, after the clone and before
the build:

- `patches/*.patch` — unified diffs against the pinned commit, applied
  in filename order with `git apply` (each was verified to apply cleanly
  and the touched Swift files were syntax-checked):
  - `001-translation-force-system.patch` — `TranslationConfiguration`:
    force `auto` to `.system`, so chat translation uses the on-device
    Apple Translation implementation regardless of the server-delivered
    `translations_auto_enabled` value.
  - `002-translation-panel-without-premium.patch` —
    `ChatTranslationPanelNode`: the translation panel's toggle/close no
    longer requires Premium.
  - `003-translation-panel-visibility.patch` —
    `ChatControllerContentData`: initialise `maybeSuggestPremium` to
    `true`, so the chat translation state is computed for every chat
    instead of only after the premium-suggestion threshold (or for
    Premium / auto-translate peers).
  - `004-branding-display-name.patch` — `Telegram/BUILD`: display name
    (and main-app bundle name) `Telegram` → `Foxgram`. The name is
    hardcoded in plist fragments in `Telegram/BUILD`, so it cannot be
    set from the build configuration JSON.
- `assets/icon/` — the original Foxgram fox icon, generated by
  `scripts/generate_icon.py` (one polygon geometry, PIL-rendered):
  `Telegram.icon/` is an Icon Composer package that replaces
  `Telegram/Telegram-iOS/Telegram.icon` in the cloned tree — at 12.10
  the main app icon is compiled from that package, not from an
  `.appiconset`. `AppIcon.appiconset/` holds the same artwork as a
  classic PNG set mirroring the stock icon filenames/sizes.

Phase 1 builds are published under the Release tag `phase1-v0.2.0`.

## API credentials

The build configuration reads the repository secrets `FOXGRAM_API_ID` and
`FOXGRAM_API_HASH`. They **are set** (Aqua entered them directly in the
repository settings; the values never pass through this repository's
files or chat), so builds use the real credentials and the IPA can log
in. Only if the secrets were absent would the build fall back to
clearly-dummy placeholder values (api_id `1234567`, api_hash
`0123456789abcdef0123456789abcdef`), with which an IPA **cannot log in
to Telegram**.
